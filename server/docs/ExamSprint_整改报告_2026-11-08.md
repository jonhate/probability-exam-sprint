## 4. 必须修复的缺陷

### R01 / P1：修正间隔复测判定

**事实与证据**

- [learning.py:67](C:/Users/26357/Desktop/跨保/exam_sprint/engine/learning.py:67) 对同一考点的任意两条成功记录比较时间；间隔达到 30 分钟即可标记 retained。
- 没有要求记录对应同一道题，或经过明确定义的同一能力复测。
- 静态版存在相同逻辑，见 [static_bridge.js:91](C:/Users/26357/Desktop/跨保/exam_sprint/web/static_bridge.js:91)。
- 最小复现：q003 正态对称性和 q010 二项分布各独立答对一次，间隔 31 分钟，系统显示“间隔复测通过”。两题都没有被再次测试。

**评价**：当前标签超过了证据支持的范围。

**修改要求**

1. 明确定义“间隔复测”的对象：同题保持、同能力的新题验证，应分别记录和解释。
2. 复测记录必须能关联前次证据及本次验证对象，不能仅以同考点、两条成功和时间差判定。
3. 明确近期失败、辅助作答和历史成功对当前状态的影响，避免历史成功直接覆盖新的不确定性。
4. 后端与静态版采用同一证据规则，并为规则设置版本。

**验收标准**

- 上述 q003/q010 各做一次的情况不再显示“间隔复测通过”。
- 未达到间隔阈值、使用辅助或部分完成的记录不能通过独立复测。
- 满足明确定义的复测条件时才显示对应标签；能查看其关联记录。
- 两端对同一输入和时钟产生一致结果。

### R02 / P1：保存失败不得返回成功

**事实与证据**

- [static_bridge.js:25](C:/Users/26357/Desktop/跨保/exam_sprint/web/static_bridge.js:25) 吞掉 localStorage.setItem 异常。
- [static_bridge.js:324](C:/Users/26357/Desktop/跨保/exam_sprint/web/static_bridge.js:324) 随后照常返回成功。
- 最小复现：模拟存储抛出配额异常，接口仍返回 HTTP 200、ok:true；内存中存在答题记录，持久存储条目为零。
- 考试设置保存也吞掉异常，见 [static_bridge.js:279](C:/Users/26357/Desktop/跨保/exam_sprint/web/static_bridge.js:279)。

**推断**：刷新或退出后，这些记录会丢失，用户却已看到成功反馈。

**修改要求**

1. 持久化失败时返回明确失败，并在 UI 提示可重试。
2. 先确认保存成功，再更新“已记录”等完成状态；或提供清晰的未保存状态和回滚机制。
3. 重试不得重复追加同一条记录。
4. 进度与考试设置都执行相同的失败处理原则。

**验收标准**

- 模拟配额不足、存储不可写时，不出现已保存成功反馈。
- 恢复存储后可重试成功，且只有一条记录。
- 刷新后成功记录仍存在；失败设置不得被描述为已持久保存。

### R08 / P2：为空状态设计实际有效的下一步

**事实与证据**

- [app.js:307](C:/Users/26357/Desktop/跨保/exam_sprint/static/app.js:307) 对多种空状态展示相同“继续，给我下一步”按钮，并同时展示其他入口。
- [app.js:1467](C:/Users/26357/Desktop/跨保/exam_sprint/static/app.js:1467) 的继续动作只重设 15 分钟会话预算。
- session_done 可重开会话，不是死路。
- expired 点击继续仍为 expired；可通过考试设置恢复。
- rest 点击继续仍为 rest。

**修改要求**

| 状态 | 应提供的主要下一步 |
|---|---|
| ready | 开始当前唯一突出任务 |
| session_done | 明确开始下一段，并说明新预算 |
| expired | 直接进入日期更新，解释为何不能继续安排 |
| rest | 解释每日预算已用完；如允许调整，提供明确调整动作 |
| waiting | 显示复测时间；到时刷新任务，或提供明确刷新动作 |
| short_budget | 提供实际可完成任务，或明确提示需要增加多少预算 |
| no_questions | 按本地/静态版能力提供真实可用的资料或课程入口 |

**验收标准**

- 每个状态只有一个突出主要动作，备用入口可折叠。
- 按钮不承诺无法完成的行为；不能只重复回到相同状态而无解释。
- 当前过期默认课程可以通过明确流程更新日期并产生任务。
- 保留每日预算及复测约束，不为消除空状态而无说明绕过它们。

## 5. 设计优化项

### O01：将零基础先修工具纳入调度

**事实**：首页调度主要根据题目、考点及历史记录选题，见 [learning.py:38](C:/Users/26357/Desktop/跨保/exam_sprint/engine/learning.py:38)；没有将零基础工具的先修依赖作为显式调度条件。

**推断**：完全零基础用户可能先遇到需要尚未学习工具的题目。本次没有真实学习实验来确认其发生频率或效果损失。

**建议要求**

- 用明确、可解释的先修关系连接工具卡、示例、评分点及题目。
- 诊断发现缺少先修能力时，可以安排短讲解或示例，再给验证任务。
- 仍然保持首页一个突出下一步，不要求用户先自选水平。
- 只有资料不足或确有必要时才询问用户，不增加例行选择负担。

**验收方式**：构造缺少积分、分段函数等先修证据的用户记录，检查系统是否给出合理、可完成且解释明确的下一步。这里验收的是流程，不等于证明提分效果。

### O02：校准参数并限定科学性声明

**事实**

**评价**：检索练习、分散练习和数学交错练习的方向有研究依据，但不能直接证明本项目具体调度参数有效。

参考研究：[Roediger & Karpicke, 2006](https://pubmed.ncbi.nlm.nih.gov/16507066/)、[Rohrer 等数学交错练习随机试验](https://doi.org/10.1037/edu0000367)。

**建议要求**

- 评估任务是否可完成、是否反复卡住、是否验证保持和迁移；不能只统计点击、做题数或即时正确率。
- 明确预算统计边界：当前主要统计记录的题目停留时间，不能宣传为全部学习时间。
- 有真实比较证据后再调整提分、保分及目标路线表述。

**验收方式**：参数有版本、解释和可复核依据；产品文案准确反映证据强度。没有真实实验时，应明确写为尚待验证。
